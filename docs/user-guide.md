# Посібник користувача HotelBooking

Консольний застосунок для адміністратора готелю: бронювання номерів, оплата,
заселення, скасування, виселення, пошук і звіт про заповнюваність.

## Запуск

```
dotnet run --project HotelBooking.App
```

Можна вказати іншу теку з даними: `dotnet run --project HotelBooking.App -- D:\hotel-data`.

Одразу після запуску видно версію, скільки записів завантажено, і меню:

```
HotelBooking v1.0.0
Завантажено: 40 номерів, 80 гостей, 60 бронювань. Журнал: ...\logs\app.log

=== HotelBooking ===
1. Вільні номери на період
2. Забронювати номер (UC-01)
3. Оплатити бронювання (UC-03)
4. Заселити гостя (UC-02)
5. Скасувати бронювання (UC-02)
6. Виселити гостя (UC-04)
7. Знайти бронювання (UC-05)
8. Заповнюваність за тиждень (UC-06)
0. Вихід
Ваш вибір:
```

Дати вводяться як `дд.мм.рррр`, суми - з комою (`5940,00`). Дата виїзду не
вводиться: її рахує програма як «дата заїзду + кількість ночей». День виїзду вже
вільний для наступного гостя.

Ціна ночі залежить від сезону: листопад-березень х1,00, квітень-травень і
вересень-жовтень х1,20, червень-серпень х1,50, 24.12-07.01 х1,80.

Нижче наведено справжній вивід програми. Після кожного сценарію знову
показується меню, тут воно скорочене до `[меню]`.

## Сценарій 1. Знайти вільний номер і забронювати

```
Ваш вибір: 1
Дата заїзду (дд.мм.рррр): 01.12.2026
Кількість ночей: 2
Вільно 35 номерів з 01.12.2026 по 03.12.2026:
  101   Family    місць 4  2 150,00 грн/ніч
  103   Standard  місць 2  1 100,00 грн/ніч
  104   Comfort   місць 3  1 650,00 грн/ніч
  ...
[меню]
Ваш вибір: 2
Ідентифікатор гостя: 12
Номер кімнати: 104
Дата заїзду (дд.мм.рррр): 24.12.2026
Кількість ночей: 2
Створено бронювання № 61: номер 104, ночей 2, до сплати 5 940,00 грн.
```

Тут обидві ночі святкові: 1650 х 1,80 х 2 = 5940 грн.

## Сценарій 2. Оплатити і заселити

```
Ваш вибір: 3
Номер бронювання: 61
До сплати 5 940,00 грн. Сума: 5000
Відмовлено (booking.amount): Сплачено 5000.00 грн, треба 5940.00 грн
[меню]
Ваш вибір: 3
Номер бронювання: 61
До сплати 5 940,00 грн. Сума: 5940
Бронювання № 61 оплачено і підтверджено.
[меню]
Ваш вибір: 4
Номер бронювання: 61
Гостя за бронюванням № 61 заселено.
```

Заселити неоплачене бронювання не вийде: програма відповість
`Відмовлено (booking.check-in)` і підкаже спершу оплатити. Виселення (пункт 6)
показує підсумок: `Гостя виселено. Підсумок за проживання 5 940,00 грн.`

## Сценарій 3. Скасувати бронювання

```
Ваш вибір: 5
Номер бронювання: 61
Причина: змінились плани
Бронювання № 61 скасовано: змінились плани
Бронювання № 61 скасовано.
[меню]
Ваш вибір: 5
Номер бронювання: 61
Причина:
Відмовлено (booking.cancellable): Бронювання № 61 у стані Cancelled скасувати не можна
```

Скасувати можна нове або підтверджене бронювання. Після заселення - вже ні.

## Сценарій 5. Звіт «Заповнюваність за тиждень»

```
Ваш вибір: 8
Перший день тижня (дд.мм.рррр): 23.11.2026
Заповнюваність з 23.11.2026:
  23.11 пн    0 з 40    0,0 %
  24.11 вт    2 з 40    5,0 %
  25.11 ср    1 з 40    2,5 %
  26.11 чт    1 з 40    2,5 %
  27.11 пт    3 з 40    7,5 %
  28.11 сб    3 з 40    7,5 %
  29.11 нд    3 з 40    7,5 %

```

Номер вважається зайнятим у ніч, якщо на неї є нескасоване бронювання.

## Повідомлення про помилки

Помилка вводу (формат) - програма пояснює, що не так, і питає ще раз. Після
третьої невдалої спроби повертає в меню.

| Повідомлення | Що означає | Що робити |
|---|---|---|
| `Ідентифікатор гостя - ціле число більше 0` | ввели не число, 0 або від'ємне | ввести номер гостя з картотеки |
| `Номер кімнати - від 1 до 10 символів` | поле порожнє або задовге | ввести номер, наприклад `104` |
| `Дата - у форматі дд.мм.рррр, наприклад 10.11.2026` | інший формат або неіснуюча дата (31.11) | ввести дату з крапками |
| `Кількість ночей - від 1 до 30` | 0, більше 30 або не число | довше 30 ночей бронювати частинами |
| `Стан - одне з: New, Confirmed, ...` | невідомий стан у пошуку | ввести одну з назв (регістр неважливий) |
| `Задайте хоча б одну умову пошуку` | усі поля пошуку порожні | заповнити хоча б одне |
| `Немає такого пункту, введіть число від 0 до 8.` | неіснуючий пункт меню | вибрати з переліку |

Відмова за правилом - програма показує ідентифікатор правила в дужках.

| Правило | Коли | Що робити |
|---|---|---|
| `room.exists` | такого номера немає в готелі | перевірити номер (пункт 1) |
| `guest.exists` | гостя з таким ідентифікатором немає | перевірити ідентифікатор |
| `stay.past` | дата заїзду вже минула | вибрати сьогодні або пізніше |
| `room.busy` | номер зайнятий хоча б одну ніч періоду | вибрати інший номер або дати |
| `booking.exists` | бронювання з таким номером немає | знайти його через пошук (пункт 7) |
| `booking.amount` | сума менша за потрібну | внести всю суму |
| `booking.payable` | бронювання вже оплачене або скасоване | нічого, оплата не потрібна |
| `booking.check-in` | бронювання не оплачене або вже не активне | спершу оплатити (пункт 3) |
| `booking.check-out` | гостя ще не заселено | спершу заселити (пункт 4) |
| `booking.cancellable` | гість уже заселився або бронювання закрите | скасування неможливе |

Якщо при запуску з'явилось `Не вдалося прочитати дані: ...`, значить файлу в
теці `data` немає або він пошкоджений. Відновіть його з резервної копії.

## Де лежать дані і як зробити резервну копію

Програма читає й пише теку `data` поруч із виконуваним файлом
(`HotelBooking.App/bin/Debug/net8.0/data` після `dotnet run`):

- `rooms.json` - 40 номерів, лише читається;
- `guests.json` - 80 гостей (умовні імена, пошта `@example.com`), лише читається;
- `bookings.json` - бронювання, переписується після кожної зміни.

Резервна копія - скопіювати теку `data` цілком, поки програма закрита. Відновлення -
скопіювати назад. Початкові дані лежать у теці `data` в корені репозиторію і
потрапляють у `bin` при першому складанні.

Журнал роботи - `logs/app.log` поруч із виконуваним файлом. Рядок має вигляд


```
2026-11-21 18:39:16 [WARNING] HotelBooking.Core.Services.ReservationService {UC-01 Room:104}: UC-01 відхилено, правило room.busy: Номер 104 зайнятий у цей період
2026-11-21 18:39:16 [INFORMATION] HotelBooking.Core.Services.BookingService {UC-02 Booking:61}: UC-02 гостя заселено
```

У фігурних дужках - сценарій і номер бронювання чи кімнати.
Імен і пошти гостів у журналі немає, лише номери бронювань і правила.
