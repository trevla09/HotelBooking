# Чекліст огляду коду HotelBooking

Версія стандарту 2.0.0. Повний текст правил - у [CODING_STANDARD.md](../../CODING_STANDARD.md).

У чеклісті немає нічого, що вже перевіряє машина: відступи, дужки, порядок `using` і регістр імен людина на огляді не дивиться. Вона дивиться те, чого аналізатор не бачить.

| № | Категорія | Пункт |
|---|---|---|
| Ч-01 | Іменування | Чи зрозуміло призначення типу і методу з імені, не відкриваючи тіло? Тип - іменник, метод - дієслово (N-02, N-09, N-10) |
| Ч-02 | Іменування | Чи немає затичок, транслітерації, скорочень, числових суфіксів і однолітерних імен поза лічильником циклу (п. 2.2, N-11, D-05)? |
| Ч-03 | Іменування | Чи всі терміни предметної області є в глосарії; якщо з'явився новий - чи додано його в п. 1.5 (N-18)? |
| Ч-04 | Складність | Чи немає вкладеності глибше трьох рівнів, ланцюгів `if` по стану, `return true / false`, зміни колекції в `foreach` (S-02...S-12)? |
| Ч-05 | Форматування | Чи немає рядків, довших за 100 символів, і чи довгі вирази перенесено перед оператором (F-08, F-15)? |

| Ч-18 | Тести | Чи є тест на кожну нову гілку логіки, особливо на межові дати (день виїзду = день заїзду)? |

Два правила культури огляду.

**Р-1. Зауваження стосуються коду, а не автора.** Не "ти знову забув дужки", а "у рядку 42 порушено F-09".

**Р-2. Кожне зауваження має бути виконуваним: містити конкретну дію, а не оцінку.** Не "незрозуміло", а "винесіть `0.9m` у константу `RegularDiscountRate` (D-06)". Зауваження без дії автор не може ні виконати, ні заперечити.
